# Pi Web 手机端 UX 审计与待审核优化方案

> 状态：**方案待 Later 审核，尚未实施 UI 改版**
>
> 审计环境：`https://pi.ai4child.asia`，390×844，`codex/later-custom@510d6c4`
>
> 审计原则：先保证跨设备主链路可靠，再降低高频动作成本；沿用现有视觉语言，不另造一套移动端产品。

## 1. 本次走查范围与健康度

| 步骤 | 当前健康度 | 证据与判断 |
|---|---|---|
| 进入工作区 | 可用但层级弱 | 顶栏、空工作区、输入区均可用；主内容大面积空白，同时重复显示 `π Pi Web` 与版本信息 |
| 打开手机菜单 | 可用 | 底部 action sheet 点击区域清楚，但把项目、文件、设备、主题、Session 控制和自检混在一层 |
| 选择另一台设备 | 功能正确、效率不足 | 从主界面需要“更多菜单 → 设备下拉 → 目标设备”3 次点击；下拉菜单嵌在 action sheet 内，层级重叠 |
| 切换设备 | 健康 | 不 reload document；真实旧工作区保留到目标就绪，URL 与登录不变；失败事务具备回滚 |

## 2. 已识别问题

### P0-A：高频设备切换被埋得太深

当前至少 3 次点击才能切换，而且“菜单中的下拉菜单”形成嵌套交互。用户频繁往返时，每次都要重新定位入口；当前设备名称也只有打开 action sheet 后才可见。

**拟议改法**：

1. 顶栏直接显示当前设备胶囊，例如 `Main Mac` / `Pop!_OS`，设备状态从隐藏信息升级为工作区一级上下文。
2. 点击胶囊打开单独的设备 bottom sheet，设备行直接呈现名称、当前状态、最近工作区和不可用状态；去掉 action sheet 内的二级 dropdown。
3. 顶栏空间不足时把现有 Refresh 下沉到工作区菜单或下拉刷新，保留 `项目 / 设备 / 新建 / 更多` 四个一级动作。
4. 切换后胶囊立即进入 `正在切到 Pop!_OS…` 的禁用状态；旧工作区保持可见，目标 ready 后一次性更新。失败显示原位错误与重试，不跳错误页。
5. 只有 2 台设备时，可在设备 sheet 顶部提供“切回上一台”的快速行；不采用全屏左右滑动，避免与会话/浏览器返回手势冲突。

目标：从 3 次点击降到稳定的 2 次；用户在任何时刻都能看见当前执行设备。

### P0-B：空工作区浪费首屏，信息层级重复

没有打开 Session 时，页面中部几乎全空，但又重复出现顶栏品牌与 `π Pi Web / web v0.8.4 / pi v0.83.0`。版本信息对日常任务价值很低，却占据首屏视觉焦点。

**拟议改法**：

1. 空态只保留一个产品身份，把版本移动到“关于/自检”。
2. 空态提供 2 个明确主动作：`新建 Session`、`打开最近 Session`；下方最多列 3 个当前设备最近项目。
3. 有 Session 时完全移除空态品牌区，把空间让给消息与输入。
4. 不在空态制造假数据或装饰性骨架，所有项目/Session 都来自当前设备真实目录。

### P0-C：输入区功能齐全，但移动端主次不够清楚

当前触控尺寸基本合格：顶栏按钮、Send、附件、设置均为 44px 高；输入字号为 16px。主要问题是模型全名占 260px 仍被截断、附件/模型/设置挤在同一行，用户难以快速判断“现在用哪个模型、怎么发送”。

**拟议改法**：

1. 文本区保持 16px，支持 1–5 行自然增长；Send 固定在右下，不因工具栏内容移动。
2. 第二行改成 `附件 | 简短模型胶囊 | 运行设置`，胶囊显示短名 `DeepSeek V4`；完整 Provider/模型在点击后的 sheet 展示。
3. streaming 时把 Stop 放到 Send 的固定位置，避免布局跳动。
4. 键盘打开后只保留与发送直接相关的控件；模型/高级运行设置可折叠，但不能丢失可访问名称。

### P1-A：高频工作区动作与低频管理动作混在一起

`Projects & sessions`、`Open files` 与 `Mobile self-check`、主题、Session controls 同层。前两者是高频导航，自检和主题是低频设置，混排增加扫描成本。

**拟议改法**：

- 一级工作区 sheet：设备、项目/Session、文件；
- 设置 sheet：主题、模型、Skills、Plugins、Extensions；
- 诊断页：Mobile self-check、版本与连接信息；
- Session controls 只在已打开 Session 时出现，并靠近当前 Session 标题。

### P1-B：语言与命名不统一

中文使用场景中仍出现 `New session`、`Projects & sessions`、`Open files`、`Full history`、`Mobile self-check` 等英文，设备切换提示也是英文。项目名与设备名可以保留原文，但产品动作应跟随当前语言。

**拟议改法**：补齐移动端文案 key；对设备名、模型名和项目路径不做错误翻译；状态文案使用一致动词，如“正在连接”“已切换”“连接失败”。

### P1-C：长 Session/项目列表在手机上缺少快速收敛手段

当前侧栏可展示完整树，但大量长中文标题、fork、消息数和时间同时出现，390px 下密度很高。频繁跨项目时需要滚动和辨认。

**拟议改法**：

1. 顶部提供搜索，范围明确为当前设备；
2. 默认先显示“最近项目 / 最近 Session”，完整树作为二级入口；
3. Session 行只保留两级信息：标题 + 时间/运行态，消息数与 fork 操作进入详情或滑动动作；
4. 运行中 Session 使用一致状态点，并在设备 sheet 上聚合数量，但不跨设备轮询全部详情。

## 3. 可访问性与边界场景

已确认：主要按钮高度达到 44px，输入字号 16px。仍需专项验证：

1. 设备 bottom sheet 的焦点圈、焦点锁定、关闭后焦点回到设备胶囊；
2. 切换状态使用 `aria-live` 简短播报，不能反复读完整页面；
3. 当前设备不能只靠颜色区分，需同时有文字/图标；
4. 200% 字体、横屏、刘海安全区和超长设备/模型/项目名不溢出；
5. `prefers-reduced-motion` 下不使用 View Transition 动画，但仍保持清楚的连接状态；
6. 目标离线、错路由、认证过期、App 从后台恢复时均能回到可操作状态；
7. 原设备 streaming 时切换只断开该页面连接，不 abort 远端任务；切回后 reconciliation 恢复状态。

## 4. 建议实施顺序

### 第一批：设备切换入口（建议先批准）

- 顶栏设备胶囊；
- 独立设备 bottom sheet，移除嵌套 dropdown；
- 切换中/失败/重试状态；
- 2 台设备快速回切；
- 对应组件、状态机、键盘/VoiceOver 与 390×844/430×932 视口用例。

这批只改变入口和反馈，不改 Session、API、网关或部署边界，风险最低、收益最高。

### 第二批：输入区与空态

- 多行输入与稳定 Send/Stop；
- 短模型胶囊；
- 有用的空态动作，移走版本信息；
- 键盘、安全区和长名称回归。

### 第三批：项目/Session 信息架构

- 最近项、搜索和列表降噪；
- 工作区/设置/诊断分层；
- 运行态跨设备摘要，仍避免 N×M 轮询。

## 5. 审核后才执行的验收标准

1. 两台设备连续往返 10 次：URL/document 不变，不出现空白帧，设备与路径不串线。
2. 局域网正常时切换目标：中位数 ≤ 1 秒，P95 ≤ 2.5 秒；超时必须回滚原设备。
3. 从主界面到选中另一台设备不超过 2 次点击；当前设备在顶栏持续可见。
4. 所有高频点击目标 ≥ 44×44px；输入字号 ≥ 16px；长名称在 320px/390px/430px 下不推走 Send。
5. Safari tab 与 installed PWA 各覆盖：普通切换、后台恢复、原设备 streaming、目标离线、reduced motion。
6. 自动化覆盖：状态机、回滚、焦点返回、键盘开合、文本缩放、视口截图与无障碍名称；全量 TypeScript/ESLint/Node tests 保持通过。
